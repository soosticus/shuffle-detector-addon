## What this is

A WoW Classic addon plus a Python companion that ranks crafting "shuffles" (craft something, then disenchant, sell on the AH or vendor it) from Auctionator's auction house prices.

- Target client: the "Forever" Classic client, Interface 16001, installed as `C:/Games/World of Warcraft/_classic_beta_/` (on the other machine it is `C:\Program Files (x86)\World of Warcraft`; the install path differs per machine). It exposes the modern `C_TradeSkillUI` profession API, not the classic `GetTradeSkill*` functions (the addon supports both).
- `addon/ShuffleDetector/`: `ShuffleDetector.lua` (core: item, profession, recipe and vendor recording, slash commands), `Disenchant.lua` (logs observed disenchant results), `Shuffle.lua` (secure button and step tracker), `Plan.lua` and `ItemList.lua` (generated by the companion, never hand edit).
- `companion/src/shuffledetector/`: `luaparse.py` (reads SavedVariables), `auctionator.py` (decodes the CBOR price blobs in Auctionator's SavedVariables), `deyields.py` (reads Auctionator's disenchant table file), `data_loader.py` (`Reference`, `ScanData`, `with_observed` layering), `calc.py` (per-recipe evaluation and ranking), `calculator.py` (batch planner), `plan.py` (writes Plan.lua), `addon_manager.py` and `updater.py` (install and update; `Install.auctionator_installed` drives the GUI's yellow "Auctionator is required" banner with a CurseForge link, no auto-install because CurseForge downloads need an API key or its terms), `cli.py`, `gui/app.py` (PySide6).
- `common/data/reference.json`: small hand-written seed data (mostly Tailoring). Unverified.
- Repo: `C:\Users\soost\OneDrive\Projects\ShuffleDetector`, private GitHub `soosticus/ShuffleDetector`, branch `main`. The session working directory may be a different folder (`c:\Users\soost\projects\WaveLinkRestarter`), so use absolute paths.

## Data flow

The addon writes `AHSnapshotDB` (SavedVariables, only flushed on `/reload` or logout). Prices come from Auctionator: the addon depends on it (`## Dependencies: Auctionator`) but does no scanning, and the companion decodes Auctionator's own `Auctionator.lua` (same SavedVariables folder, `auctionator.py`) into per-realm min-price "scans" (`ScanData.scans`, realm keys as Auctionator names them, freshest first). The companion reads both, `Reference.with_observed(scan)` layers recorded item names, sell prices, vendor buy prices, recipes and observed disenchant yields over the seed data, `calc.rank` ranks them, and the GUI or CLI shows the result and can send a `Plan.lua` back to the addon.

What the addon records (details in FORMAT.md; prices are not recorded, see below): per character and profession the skill, learned `recipes` (name, spell, item, makes, reagents) and unlearned `available` recipes (plus trivial level and source text); `items` (name, vendor sell price); `vendor` (buy prices from the merchant window); `disenchants` (item disenchanted, quality, item level, and the loot, one entry per successful cast). Recipes are captured when a profession window opens (with retries, because no final list event arrives), and the profession name is taken from `GetProfessionInfoByRecipeID` because the window's own name lags after switching windows.

## Environment quirks (Windows, Git Bash)

- Tests: `cd companion && PYTHONPATH=src ../.venv-$(hostname)/Scripts/python.exe -m pytest -q -p no:cacheprovider tests` (85 pass). `python run.py --test` also works.
- The checkout (including `.git`) lives in OneDrive and is used from two machines, each with its own `.venv-<hostname>` (made by `run.py`). OneDrive once restored an older `.git/refs/heads/main` after a commit; if `git log` is missing a commit you made, check `git reflog` and fast-forward with `git update-ref`. Prefer finishing a commit and letting sync settle before switching machines.
- Source files are CRLF. The Edit tool can trip on that, so for multi-line edits use a Python script that reads with `newline=''`, normalises to `\n`, edits, and writes back with `\r\n`. Chaining several heredocs in one Bash call failed once; keep them in separate calls.
- Bash `/tmp` is not the same as the Windows Python `/tmp`: pipe data into python rather than saving to `/tmp` and reading it from Windows Python.
- Lua syntax check: needs the `lupa` package (it lived in `/tmp/sdvenv`, which may need recreating with `python -m venv /tmp/sdvenv` then `pip install lupa`). Run `python -c "import lupa; l=lupa.LuaRuntime(); f=l.eval('function(p) local f,e=loadfile(p) return e end'); print(f('addon/ShuffleDetector/ShuffleDetector.lua'))"`; `None` means it parses. A lupa smoke harness that stubs the WoW API was kept in `/tmp` (not in the repo); rebuild a small one if needed.
- Deploy the addon for testing: prefer the companion's Addon > Install (or `addon_manager.install_addon`), which stamps the `.toc` placeholder as `dev-<sha>`. If you copy files by hand (`ShuffleDetector.lua`, `ShuffleDetector.toc`) to `C:/Games/World of Warcraft/_classic_beta_/Interface/AddOns/ShuffleDetector/`, replace `@project-version@` in the copied `.toc` with `dev-<git rev-parse --short=7 HEAD>` so the user can see what loaded, then ask the user to `/reload`. The version is never bumped in the repo: releases take it from the tag.
- SavedVariables: `C:/Games/World of Warcraft/_classic_beta_/WTF/Account/50021243#1/SavedVariables/ShuffleDetector.lua`. Test characters: Arand (Herbalism, Cooking, Alchemy 0, Fishing) and Suest (Tailoring 45, Enchanting 29, Cooking 0).
- The integrated browser tool was unreliable here (AbortError); use curl, and only for sources whose terms allow it.
- WoW API behavior cannot be verified from here; only the user can test in game. Write nil-safe code (`pcall`, existence checks) with retries, and use `/shuffledetector recipes` (prints the window's recipe counts and what is saved) as the diagnostic, and `/shuffledetector log` (hidden ring buffer in `AHSnapshotDB.log` with button clicks, casts and game errors; add new diagnostics with `ns.log`, not `say`).
