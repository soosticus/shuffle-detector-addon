## What this is

A WoW Classic addon plus a Python companion that ranks crafting "shuffles" (craft something, then disenchant, sell on the AH or vendor it) from auction house scans.

- Target client: the "Forever" Classic client, Interface 16001, installed as `C:/Games/World of Warcraft/_classic_beta_/` (on the other machine it is `C:\Program Files (x86)\World of Warcraft`; the install path differs per machine). It exposes the modern `C_TradeSkillUI` profession API, not the classic `GetTradeSkill*` functions (the addon supports both).
- `addon/ShuffleDetector/`: `ShuffleDetector.lua` (core: item, profession, recipe and vendor recording, slash commands), `Disenchant.lua` (logs observed disenchant results), `Scan.lua` (AH scan, Auctionator import), `UI.lua` (AH tab), `Shuffle.lua` (secure button and step tracker), `Plan.lua` and `ItemList.lua` (generated by the companion, never hand edit).
- `companion/src/shuffledetector/`: `luaparse.py` (reads SavedVariables), `data_loader.py` (`Reference`, `ScanData`, `with_observed` layering), `calc.py` (per-recipe evaluation and ranking), `calculator.py` (batch planner), `plan.py` (writes Plan.lua), `addon_manager.py` and `updater.py` (install and update), `cli.py`, `gui/app.py` (PySide6).
- `common/data/reference.json`: small hand-written seed data (mostly Tailoring). Unverified.
- Repo: `C:\Users\soost\OneDrive\Projects\ShuffleDetector`, private GitHub `soosticus/ShuffleDetector`, branch `main`. The session working directory may be a different folder (`c:\Users\soost\projects\WaveLinkRestarter`), so use absolute paths.

## Data flow

The addon writes `AHSnapshotDB` (SavedVariables, only flushed on `/reload` or logout). The companion reads it, `Reference.with_observed(scan)` layers recorded item names, sell prices, vendor buy prices, recipes and observed disenchant yields over the seed data, `calc.rank` ranks them, and the GUI or CLI shows the result and can send a `Plan.lua` back to the addon.

What the addon records (details in FORMAT.md): AH scans; per character and profession the skill, learned `recipes` (name, spell, item, makes, reagents) and unlearned `available` recipes (plus trivial level and source text); `items` (name, vendor sell price); `vendor` (buy prices from the merchant window); `disenchants` (item disenchanted, quality, item level, and the loot, one entry per successful cast). Recipes are captured when a profession window opens (with retries, because no final list event arrives), and the profession name is taken from `GetProfessionInfoByRecipeID` because the window's own name lags after switching windows.

## Environment quirks (Windows, Git Bash)

- Tests: `cd companion && PYTHONPATH=src ../.venv-$(hostname)/Scripts/python.exe -m pytest -q -p no:cacheprovider tests` (53 pass). `python run.py --test` also works.
- The checkout (including `.git`) lives in OneDrive and is used from two machines, each with its own `.venv-<hostname>` (made by `run.py`). OneDrive once restored an older `.git/refs/heads/main` after a commit; if `git log` is missing a commit you made, check `git reflog` and fast-forward with `git update-ref`. Prefer finishing a commit and letting sync settle before switching machines.
- Source files are CRLF. The Edit tool can trip on that, so for multi-line edits use a Python script that reads with `newline=''`, normalises to `\n`, edits, and writes back with `\r\n`. Chaining several heredocs in one Bash call failed once; keep them in separate calls.
- Bash `/tmp` is not the same as the Windows Python `/tmp`: pipe data into python rather than saving to `/tmp` and reading it from Windows Python.
- Lua syntax check: needs the `lupa` package (it lived in `/tmp/sdvenv`, which may need recreating with `python -m venv /tmp/sdvenv` then `pip install lupa`). Run `python -c "import lupa; l=lupa.LuaRuntime(); f=l.eval('function(p) local f,e=loadfile(p) return e end'); print(f('addon/ShuffleDetector/ShuffleDetector.lua'))"`; `None` means it parses. A lupa smoke harness that stubs the WoW API was kept in `/tmp` (not in the repo); rebuild a small one if needed.
- Deploy the addon for testing: copy the changed addon files (usually `ShuffleDetector.lua` and `ShuffleDetector.toc`) to `C:/Games/World of Warcraft/_classic_beta_/Interface/AddOns/ShuffleDetector/`, bump `## Version` in the `.toc` each time so the user can see what loaded, then ask the user to `/reload`.
- SavedVariables: `C:/Games/World of Warcraft/_classic_beta_/WTF/Account/50021243#1/SavedVariables/ShuffleDetector.lua`. Test characters: Arand (Herbalism, Cooking, Alchemy 0, Fishing) and Suest (Tailoring 45, Enchanting 29, Cooking 0).
- The integrated browser tool was unreliable here (AbortError); use curl, and only for sources whose terms allow it.
- WoW API behavior cannot be verified from here; only the user can test in game. Write nil-safe code (`pcall`, existence checks) with retries, and use `/shuffledetector recipes` (prints the window's recipe counts and what is saved) as the diagnostic.
